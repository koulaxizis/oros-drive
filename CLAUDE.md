# orOS Drive: notes for contributors and agents

- Go 1.24, no cgo. `gofmt`, `go vet ./...`, `go test ./...` before every PR.
- The vault format is owned by koulaxizis/oros (`sync.js`, `vault.js`, `OROS_BIBLE.md` "vault.js"). This repo follows it; never invent format changes here. Any change that touches `vault/` must keep `OROS_SRC=<oros checkout> go test ./interop/` green (CI runs it against orOS main).
- Implement the Bible's VD rules exactly (VD-1 absent manifest deletes nothing, VD-4 local wins, VD-5 queue generations, VD-H hash check, FILES-V conflict copies). Each one came from a real data loss.
- `vault/testdata/` vaults were written by the real vault.js via `interop/vaultjs.cjs`; regenerate them with it, never by hand.
- Free forever, MIT, no Google dependencies, each user signs in with their own Dropbox (app key `wnohlxz79ie8w3e`, the orOS sync app).
- Platforms: Windows, Linux, Android first; Mac best effort.
- `mirror/` follows the same rules on both sides: a deletion needs a Base (so a fresh or lost state never deletes), a local file is re-checked right before it is overwritten or removed, the manifest is committed only on the revision read (a refused write re-runs the whole pass), and removed local files go to the trash. Every rule has a test in `mirror/engine_test.go` and the browser round trips in `interop/mirror_test.go`; keep both green.
- `vdisk/` (the disk as a file system) follows the same rules: writes commit on the revision read, a file changed elsewhere while open here is kept as a conflict copy, a deletion spares files changed since they were listed, downloads are hash-checked, `mirror.Ignored` names stay local (scratch). Tests in `vdisk/disk_test.go`; `vdisk/fusefs` has a real-mount test that skips without FUSE. `vdisk/cloudfiles` (Windows Explorer) keeps the same rules with placeholders: only in-sync placeholders are updated or removed, deletes and renames reach orOS before Windows carries them out, no manifest deletes nothing, more than 50 deletions wait; the engine is tested with a fake folder (`engine_test.go`), the Windows side against the real Cloud Files driver in CI (`cfapi_windows_test.go`; Windows calls the provider only for other processes' changes, so the test deletes and renames through cmd.exe). Struct layouts are checked at compile time.
- `webdav/` (WebDAV and Nextcloud as the cloud) follows sync.js `webdavProvider` exactly: `<dir>/vault/<key>`, the ETag is the revision, `If-None-Match: *` / `If-Match` for the manifest and key file, nothing is saved before `Probe` passes (same checks and `dav-…` codes as `davProbe`), conditional writes are never chunked or retried, a `201` to an `If-Match` PUT is taken back and read as a conflict. Signing in to another cloud makes every folder's next pass a first sync (`mirror.NoteCloud`). Tests: `webdav/webdav_test.go` (fake server `webdav/davtest`), `vault/storetest` (the promises every store keeps), `interop` `TestOverWebDAV` (real sync.js over WebDAV), and in CI a real WsgiDAV (`interop/davserver.py`, `TestRealServer`).
- Object clean-up (`vault/clean.go`, wave 7) removes only `objects/` keys that no manifest entry names (keyed and legacy name both count) and that the provider stored 30+ days ago; no manifest, no key, or under 90% of named objects listed removes nothing; the manifest revision is checked before every removal. It runs only when the person asks (settings page, `orosdrive usage --clean`). Tests in `vault/clean_test.go`. orOS itself does not clean up ("object GC deferred" in the Bible), so this must stay at least as cautious as above.
- The settings page (`app/web`) puts app data into the page only through `textContent`; every API call needs the cookie, POSTs also the `X-OD` header, and the host must be 127.0.0.1/localhost. EN + EL for every string.
- Do not tag a release that uploads to `/internal/Drive` unless the orOS on-demand change (VD-OD, oros PR #438) is live on useoros.online.
- The Windows setup (`packaging/windows/oros-drive.iss`, Inno Setup, per user) writes the same Run value as the app, stops the app before installing over it, and on uninstall runs `orosdrive mount off` (an Explorer folder must not stay registered) and deletes settings only on a yes, never `Trash` or the mirrored folders. `test-setup.ps1` runs in the Release workflow, also on PRs that touch `packaging/`.
